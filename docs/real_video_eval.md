# 真实视频泛化评估记录

## 素材

- 来源：抖音「沈阳汽车陪练」学校路段视频（用户手动保存为 `D:\edge.download\dl.mp4`）
- 规格：1920×1080 / 30fps / 288 帧 / 9.6 秒 / 2.7 MB
- 场景：夜间、行车记录仪第一视角，画面主要是前车车尾、路灯、护栏反光、远处小车
- **注意**：这是移动机位，只用于评估「能不能检出车」，**不能用于进出计数**——虚拟线判定要求摄像机静止

## 方法

```
python tools/eval_real_video.py --video <视频路径> --every 4 --max-samples 72 --conf <阈值>
```

抽帧 72 张，模型 `models/car_yolo.onnx`（YOLO11n，4 类，298 张网络车型照片训练，
验证集 mAP50 = 0.799）。

## 结果

| 置信度阈值 | 检出框 | 每帧框数 | 零检出帧 | 平均置信度 | 平均框面积 |
|---|---|---|---|---|---|
| 0.25（默认） | 106 | 1.47 | 20/72 (27.8%) | 0.535 | 6.1% |
| 0.15 | 142 | 1.97 | 14/72 (19.4%) | 0.448 | 6.5% |
| 0.10 | 168 | 2.33 | 9/72 (12.5%) | 0.398 | 6.7% |

类别分布（conf = 0.25）：轿车 74 / SUV 31 / 客车 1 / 货车 0。
该视频里几乎没有货车与客车，**不能据此判断这两类的识别能力**。

## 观察

1. 框住的都是真车，未发现把路灯、护栏、文字误检成车 → 精确率尚可。
2. 漏检明显：近处白色 MPV、远处多辆车、部分近处车都没框住 → 召回偏低。
3. 类别混淆：两辆明显是 SUV/MPV 的车被判为 `sedan`。
4. 平均置信度从同域合成视频的 0.848 降到 0.535，域差异显著。
5. 降低阈值可多召回真车（新增框多数仍是真车），但近处白色 MPV 依然漏检
   → **不是阈值问题，是训练域缺失**。

## 原因

训练集是白天、清晰、单车居中的车型照片（多为侧面 / 前 3/4 视角）；
真实视频是夜间、车尾视角、远景小车、运动模糊与灯光干扰。两者域不匹配。

## 第二个视频：固定机位俯拍（找到并修复了首因）

- `D:\edge.download\dl (1).mp4`：1080×1920 竖屏 / 30fps / 673 帧 / 22.4 秒，
  白天高处俯拍双向多车道，车流密集、远景小车多，含电动车/行人与一辆蓝色大巴。
  镜头固定，但片内有几处取景变化（剪辑），没有随车运动。

### 整图推理（conf = 0.25，抽 84 帧）

| 指标 | 值 |
|---|---|
| 检出框 | 125（每帧 1.49） |
| 零检出帧 | 33/84 (39.3%) |
| 平均置信度 | 0.497 |
| 平均框面积 | 1.6% |
| 类别 | 轿车 89 / SUV 36 / 货车 0 / 客车 0 |

首帧画面里约 20 辆车，模型只框出 1 辆。

### 诊断：尺度压缩才是首因

1080×1920 竖屏整图 letterbox 到 640×640 时，等比缩放后有效宽度只剩约 360px，
远景小车缩到几像素就消失了。分块探针（沿高度切 640 高、40% 重叠的横块，
逐块推理后合并 NMS）验证：

| 帧 | 整图 | 3 块 | 5 块 |
|---|---|---|---|
| 0 | 1 | 9 | 9 |
| 336 | 1 | 3 | 5 |
| 504 | 0 | 8 | 11 |
| 616 | 0 | 6 | 10 |

### 正式实现

`detector.py` 新增 `TiledYoloOnnxDetector`：竖屏（h ≥ 1.4w）自动分块，
横屏退化为整图（横屏切块反而加重压缩）。`config.TILE_MODE` 支持
`auto / 1 / 0`，可用 `CAMPUS_TILE` 覆盖。
顺带修复 `main.py` 未把 `config.CONF_THRES` 传给检测器的 bug；
`TEST_VIDEO` 也支持 `CAMPUS_VIDEO` 环境变量覆盖，换视频不必改代码。

### 分块后重跑（同一视频、同一阈值）

| 指标 | 整图 | 分块 |
|---|---|---|
| 检出框 | 125 | **623** |
| 零检出帧 | 39.3% | **0%** |
| 平均置信度 | 0.497 | **0.588** |
| 货车 | 0 | 14 |

带框帧复核：框住的都是真车，电动车/行人/护栏没有被误检；
首帧由 1 个框提升到 7 个，近处此前漏掉的几辆车都回来了。

### 仍未解决

- `bus` 依旧为 0：末段那辆蓝色大巴分块后也没认出来（其余 9–11 个框都是 sedan/suv）。
- 极远处的小车仍有漏检。

这两项属于**类别与视角的域缺失**，需要补标注数据，不能靠工程手段解决。

### 进出计数链路

`CAMPUS_VIDEO=... python main.py --max_frames 150` 全链路正常出报表，
累计 enter 轿车 1 / SUV 1、exit 0。数字偏少是因为 5 秒内跨线车辆有限，
且片内取景切换会影响跟踪 ID；这一步验证的是**链路可用**，
计数准确性仍需连续无剪辑的固定机位长视频 + 虚拟线/跟踪阈值调优。

## 第三个视频：火电厂街拍（货车 / 客车类别验证）

> ⚠️ 同名路径 `D:\edge.download\dl.mp4` 后来被一段**全新视频覆盖**，
> 与本文开头那个 9.6 秒夜间行车记录仪不是同一份文件；
> `dl (1).mp4` 也已从下载目录移除。

- 规格：1920×1080 / 30fps / **2848 帧 / 94.9 秒 / 18.5 MB**
- 场景：白天路边街拍「大方火电厂街拍」，大量半挂牵引车、罐车、自卸货车近距特写，
  夹杂轿车 / SUV，中段出现一辆绿色公交车；顶部大红字水印、片内有价格字幕与剪辑。
- 非目标域：镜头有切换、大量特写与字幕，**只能评估检测与分类，不能做进出计数**。
- 独特价值：前两段视频几乎没有货车 / 客车，这里两类都大量出现，
  是唯一能验证 `truck` / `bus` 识别能力的素材。

### 整体结果（conf = 0.25，抽 143 帧）

| 指标 | 值 |
|---|---|
| 检出框 | 170（每帧 1.19） |
| 零检出帧 | 19/143 (13.3%) |
| 平均 / 中位置信度 | 0.621 / 0.688 |
| 平均框面积占画面 | **46.6%**（中位 48.4%） |
| 类别 | 货车 100 (0.684) / 轿车 42 (0.559) / SUV 22 (0.411) / 客车 6 (0.760) |

`truck` 与 `bus` 都正常检出，且置信度高于轿车 / SUV —— **修正了前两段视频的推断**：
此前 `truck=0 / bus=0` 是因为画面里根本没有这两类车，不是模型不会认。

### 按框面积分档（`tools/eval_real_video.py` 已内置该统计）

| 分档 | 框数 | 平均置信度 | 类别分布 |
|---|---|---|---|
| small(<30%) | 70 | 0.537 | sedan 33 / suv 16 / truck 15 / bus 6 |
| mid(30–60%) | 33 | 0.685 | truck 29 为主 |
| huge(>60%) | 67 | 0.676 | truck 56 / sedan 6 / suv 5 |

`huge` 占约 39%，说明该视频以近距特写为主，与俯拍监控（平均框面积 1.6%）
属于两个尺度域，结论不能直接外推。

### 逐帧核实（用检测器直接打印，避免误读图上小字标签）

| 帧 | 结果 | 判断 |
|---|---|---|
| 0 | sedan 0.82 / suv 0.41 / **bus 0.29** | 黑两厢 ✅；右黑轿车判成 SUV；**半挂车误判为 bus**（低置信度） |
| 120 | truck 0.85，框占 64.3% | ✅ 正确；框大是因车头+挂厢本身被画面裁切 |
| 1260 | **bus 0.92** / sedan 0.35 | ✅ 绿色公交车正确识别；**中间红色集装箱货车漏检** |
| 1440 | **suv 0.35，框占 90.9%** | ❌ 超近距车头特写被误判为 SUV |

### 观察

1. 顶部大红字水印、路边招牌、价格字幕**从未被误检成车辆**。
2. 大车**局部特写**（只拍到车头或车厢）会类别混淆，且框溢出画面边界。
3. **多车同框且大小悬殊**时，中间较小的车会漏检。
4. 整车可见时（frame 120 的半挂、1260 的公交车）类别与框都准确。

## 第四批：三段固定机位俯拍（分块方向修正 + 虚拟线标定）

> 注意：`dl.mp4` 与 `dl (1).mp4` 两个路径都被新视频**覆盖过**，
> 本文前几节描述的是旧内容，不是同一份素材。

| 视频 | 规格 | 场景 | 能否用于进出计数 |
|---|---|---|---|
| `dl (1).mp4`（新） | 1280×720 / 122.3s / 1814 帧 / 14.83fps | 白天高架密集车流，但**镜头会摇到纯天空**（frame 700 只有云和路灯顶端） | ❌ 机位不固定 |
| `dl (2).mp4` | 1080×1920 / 12.3s / 370 帧 | 白天高架俯拍，车流静止排队 | ❌ 车几乎不动 |
| `video_安宁区…top_0_2.mp4` | 1080×1920 / 10.6s / 318 帧 | 白天城市街道俯拍，密集出租车排队 | ❌ 车几乎不动 |

### 分块方向：宽幅横屏必须沿宽度切竖块

`TiledYoloOnnxDetector` 原实现只沿高度切横块（为竖屏设计）。
1280×720 横屏整图 letterbox 到 640×640 后有效画面只有 640×360，
远景小车缩没；沿高度切横块反而更糟。沿宽度切 3 块 640×720 竖块后，
有效分辨率提升到约 569×640。

单帧探针（同一模型、同一阈值）：

| 帧 | 整图 | 沿宽度切竖块 | 网格 3×3 |
|---|---|---|---|
| 0 | 1 | **10** | 8 |
| 1400 | 20 | **36** | 36 |
| 700（纯天空） | 0 | 0 | 0 |

带框帧复核：新增框全是真车，无明显重复框，远处小车被找回。
网格 9 块与竖块 3 块效果相当但慢 3 倍，故采用竖块。
`frame 700` 三种切法都是 0 框 —— 因为那一帧**画面里根本没有车**。

### 全片评估（conf 0.25，抽 61 帧）

| 方案 | 检出框 | 零检出帧 | 平均置信度 | truck / bus |
|---|---|---|---|---|
| 整图（旧 auto） | 312 | 36.1% | 0.453 | 0 / 0 |
| 强制沿高度切横块（旧 tile=1） | 374 | 32.8% | 0.472 | 0 / 0 |
| **自适应沿宽度切竖块（新 auto）** | **899** | **14.8%** | **0.515** | 2 / 2 |

回归：竖屏 v2 保持 595 框 / 0% 零检出不变；合成横屏视频 13 → 14 框
（多 1 个低置信度框），无退化。

竖屏两段在自动分块下分别是 263 框 / 46 帧（5.7 框每帧，零检出 0%）与
595 框 / 40 帧（14.9 框每帧，零检出 0%），说明分块在新城市、新取景下
泛化良好，不是对单一视频过拟合。

### 零检出率的解读陷阱

v0 的 36.1% 零检出里有一部分是**镜头拍天空**，不是模型漏检。
评估含转场 / 摇镜头的视频时，必须先看带框帧确认画面内容，
不能把零检出率直接当成模型召回指标。

### 进出计数

三段都不满足「固定机位 + 镜头不动 + 车流持续移动」，未用于计数演示。
虚拟线标定与静止车流假过车抑制见 [`docs/line_calibration.md`](line_calibration.md)。

## 结论与下一步（据六段素材修正）

1. **工程改进已完成**：分块推理改为按画面长边自适应（竖屏切横块、
   宽幅横屏切竖块），竖屏视频召回提升约 5 倍、横屏提升约 2.9 倍，
   均无需重训模型。
2. **类别能力基本够用**：货车 / 客车在整车可见时识别正确，
   「必须补 50–100 帧微调」的优先级**下调**。近距特写混淆在目标场景
   （俯拍全景、整车完整可见）不会触发，不必为它补数据。
3. **唯一确认的类别短板**：俯拍远景的客车（蓝色大巴 `bus=0`，
   近距公交 `bus=0.92`）。若需准确统计客车，只需补少量
   **俯拍角度的客车 / 大巴**样本。
4. **阈值**：`set CAMPUS_CONF=0.15` 可再降漏检；默认 0.25 暂不改。
5. **新发现并已修复**：默认 `LINE_Y=0.5` 可能落在俯拍画面空白区，
   且静止车流的框抖动会制造假过车。新增 `tools/calibrate_line.py`
   与 `MIN_TRACK_MOVE` 抑制，详见 `docs/line_calibration.md`。
6. **当前最该做的一步**：仍需补拍一段**固定机位、连续无剪辑、镜头不动、
   车流持续通过**的校门视频（白天 2–3 分钟即可），
   用 `calibrate_line.py` 标定虚拟线后跑 `main.py`，
   再用 `web_dashboard.py` 出演示素材。六段现有素材都不满足全部条件。
