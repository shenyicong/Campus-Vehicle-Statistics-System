# 创新点 3 · 实验三：真实视频端到端 A/B

> 验证问题：轨迹级车型众数投票在**完整视频链路**上到底改变了什么？
> 结论先行：它**只改变车型归属，不改变车辆总数、不改变检测框**。
> 这是方法的设计目标，但"改得对不对"必须用真值判断，不能只看数字变化。

## 1. 实验设置（单变量）

| 项 | A 组（逐帧） | B 组（轨迹众数） |
|---|---|---|
| `--cls-vote` | 关 | 开 |
| `--tile` | grid | grid |
| `--conf` | 0.25 | 0.25 |
| `--line-y` | 0.65 | 0.65 |
| `--min-move` | 0.03 | 0.03 |
| 视频 / 帧数 | `data/test_monitor.mp4` / 600 | 同左 |

虚拟线 0.65 由 `tools/calibrate_line.py` 标定得出（该线跨线 2 进 / 2 出，
与「4 辆车各穿线一次」真值吻合）；**不要用默认 0.5**，实测 0.5 会报 10 进 / 9 出。

```bash
python tools/eval_count_video.py --video data/test_monitor.mp4 --tile grid \
  --line-y 0.65 --max-frames 600 --no-cls-vote --out data/eval_cls_A
python tools/eval_count_video.py --video data/test_monitor.mp4 --tile grid \
  --line-y 0.65 --max-frames 600 --cls-vote --out data/eval_cls_B
```

## 2. 结果

| 指标 | A 组 | B 组 | 是否变化 |
|---|---|---|---|
| 检出框总数 | 707 | 707 | ❌ 不变 |
| 检测类别分布 | sedan 605 / suv 98 / truck 4 / bus 0 | 同左 | ❌ 不变 |
| 累计进 / 出 | 10 / 9 | 10 / 9 | ❌ 不变 |
| 进-轿车 / SUV | 9 / 1 | 10 / 0 | ✅ 变化 |
| 出-轿车 / SUV | 7 / 2 | 9 / 0 | ✅ 变化 |

结果目录：`data/eval_cls_A/`、`data/eval_cls_B/`，各含 `summary.json`、
带框可视化帧、报表 CSV/XLSX。

## 3. 怎么解读（重要）

**已证明的**：轨迹投票完全不改变检测层（框数、类别分布逐项相同），也不改变
跨线总数（进 10 / 出 9 一致）。它只在"某条已计数轨迹最终算哪个车型"上生效，
把逐帧偶尔判成 SUV 的轨迹整体改判为轿车。这验证了方法的**作用范围可控**——
不会像调 conf 那样连带改变检出数量，也不会破坏已有的进出总数实验数字。

**尚未证明的**：B 组把 SUV 归零**不等于正确**。合成视频里那几辆车的真实车型
需要人工逐帧核对（真值来自 `detector.py` 里的 4 辆车设定：轿车/SUV/货车/客车
各一辆，但模型实际把绝大多数帧判为 sedan）。如果真值确实含 SUV，那么 B 组
把整条轨迹锁成轿车就是"把错检固化了"——这恰恰是众数投票的已知风险（见
`docs/ab_innovation_cls_vote.md` 第 8 节），不是改进。

**因此报告里应这样写**：实验三用于说明"轨迹投票只影响车型统计口径、不影响
总数"，作为方法作用范围的验证；**正确性判据以实验一（合成已知真值，
A 73.12% → B 100%）和实验二（人工复核真值图）为准**，不要拿本实验的 SUV 归零
直接宣称准确率提升。

## 4. 改进建议

- 用带人工车型标注的固定机位视频重跑本实验，才能给出可信的"车型准确率提升"；
- 或把 `docs/examples/cls_gt_example.json` 的真值按人工复核补全后跑实验二；
- 本实验的 600 帧产出可直接作为"方法不影响总数"的对照表写进实验报告。
