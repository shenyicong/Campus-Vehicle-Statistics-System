# 创新点 3 A/B 验核：轨迹级车型众数投票

> 把车型判定从「当前帧」提升到「整条轨迹生命周期」，用多数帧纠正单帧错检。
> 全部改造都在推理侧，**不重训、不替换本地权重**，因此不影响已有的
> 125→623、零检出 39.3%→0%、进 54 / 出 18 等实验数字。

## 1. 方法原理与代码落点

| 组 | 车型判定方式 | 代码位置 |
|---|---|---|
| A（基线） | 取当前帧检测类别 | 原 `tracker.py:40` 的 `t["cls"] = dets[best_i][4]` |
| B（改进） | 取整条轨迹的类别众数 | `IoUTracker._voted_cls()` |

B 组在每条轨迹上维护三个量：

- `cls_votes`：`{类别索引: 命中帧数}`，每命中一帧投一票；`miss` 帧不投票；
- `last_cls`：当前帧的原始检测类别；
- 对外输出的 `cls = argmax(cls_votes)`；**平票时退化为 `last_cls`**，与 A 组语义一致，避免人为制造差异。

投票只改对外暴露的 `cls`，不写回 `cls_votes`，防止自投票放大。无论开关状态，这三个量都会照常维护，所以 A/B 切换只影响输出判定，匹配、miss、活跃轨迹过滤完全相同。

## 2. 开关在哪（单变量切换）

| 使用场景 | A 组 | B 组 |
|---|---|---|
| `config.py` 全局 | 默认（不设环境变量） | `set CAMPUS_CLS_VOTE=1` |
| `tools/eval_count_video.py` | `--no-cls-vote` | `--cls-vote` |
| `main.py` | 自动读 `config.CLS_VOTE` | 同左 |

## 3. 实验一：离线合成轨迹（无需模型/视频/标注）

```bash
python tools/eval_cls_confusion.py --out out/cls_ab_demo
```

默认参数：每类 40 条轨迹、每条 12 帧、单帧误判率 0.25、随机种子 42（结果可复现）。

本轮实测结果：

| 组 | sedan | suv | truck | bus | 总体准确率 |
|---|---|---|---|---|---|
| A 逐帧判定 | 0.675 | 0.775 | 0.700 | 0.775 | **73.12%** |
| B 轨迹众数 | 1.000 | 1.000 | 1.000 | 1.000 | **100.00%** |

准确率提升 **+26.88 个百分点**，四类 F1 均由 0.65~0.80 提升到 1.00。

⚠️ **这个 100% 是理想上限，不是真实场景指标**：合成数据里错误帧相互独立，12 帧中同一类错误帧超过半数的概率极低。它证明的是「机制有效」，报告中必须标明是合成验证，不能冒充真实视频结果。

产物：`confusion.txt`（两组矩阵与逐类 P/R/F1）、`confusion.csv`、`confusion.png`（并排热力图）、`summary.json`。

## 4. 实验二：真实图片上的类别混淆矩阵

```bash
python tools/eval_cls_confusion.py \
  --gt docs/examples/cls_gt_example.json \
  --out out/cls_ab_gt --vote-frames 8
```

真值 JSON 格式（`labels` 是该图内所有目标车辆的类别索引列表）：

```json
{
  "classes": ["sedan", "suv", "truck", "bus"],
  "samples": [
    {"image": "path/to/case.jpg", "labels": [1, 0, 0]}
  ]
}
```

类别索引：`0=轿车 1=SUV 2=货车 3=客车`。**小孩玩具车不属于车辆，不要标**。

脚本把每张图的检测结果重复 `--vote-frames` 帧并按 `--noise` 注入类别噪声，模拟同一辆车在视频中的连续观测；A 组直接用原始检测结果，其余参数（conf / tile / 图片）两组完全相同。

**判据**：B 组混淆矩阵非对角元应减少；重点看三车拼图是否稳定输出 `1 SUV + 2 轿车`。

⚠️ **本轮实测（示例真值，仅供参考）**：A 组 37.50%、B 组 37.50%，打平；两组非对角分布不同（A 把货车判成客车/轿车，B 判成 SUV/客车），说明噪声确实同时作用于两组。但只有 2 张图、8 个预测样本，差异不具统计意义；脚本在样本数 <30 时会主动提示。

示例真值里第二张图的车辆数量是**占位值**，且静态图只能构造伪时序，因此**不要把这套结果当成正式结果**。此模式用于验证流程与真值格式；主结果用实验一（160 样本合成）和实验三（真实视频连续帧）。

## 5. 实验三：真实视频端到端计数

```bash
python tools/eval_count_video.py --video <视频> --tile grid --line-y 0.65 \
  --no-cls-vote --out data/eval_cls_A
python tools/eval_count_video.py --video <视频> --tile grid --line-y 0.65 \
  --cls-vote --out data/eval_cls_B
```

对比两次 `summary.json` 的 `counting.per_class`：投票改变的是**按车型计的进/出分布**，总数可能不变——这正是要说明的点：错检纠正体现在车型归属，而不是车辆总数。

## 6. A/B 实验四条纪律

1. **单变量**：每次只切 `cls_vote`，conf / line_y / 视频 / 权重 / tile 全部固定；
2. **先定真值再跑**：合成轨迹真值天然已知；真实图片必须人工复核后再跑；
3. **分组报告**：按车型列 P/R/F1，不要只看总体均值；
4. **写清成本**：投票只多一个计数字典，每帧 O(1) 追加，推理耗时与 A 组基本相同（这是相对重训方案的优势）。

## 8. 边界与风险

- 轨迹过短（<3 帧）时投票退化为逐帧判定，收益有限；平票设计保证不会比 A 组更差；
- 若某车型在长轨迹中持续被误判（系统性偏差），投票会固化错误，需靠数据增强解决——那是创新点之外的另一个问题；
- 实验数据仅来自合成验证与本地回归素材，不涉及任何个人课程材料。
